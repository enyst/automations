1. Establish the baseline
Record the exact main SHA, Node/npm versions and lockfile. Create clean, isolated baseline and candidate worktrees at that SAME SHA. Keep dependency versions and environment identical. Read package.json, tsconfigs, knip config, package exports and build/test scripts instead of guessing their commands.
Run knip in normal AND --production mode and tsc --noUnusedLocals using the repo's actual project config. Use the repo's installed knip if available; otherwise use an isolated, exact-version-pinned knip installation and record the version. Never update the repository's manifest or lockfile to install analysis tools. Knip/tsc findings are candidates only, not deletion proof. If analysis cannot run, report BLOCKED; do not silently use grep alone.

2. Confirm EVERY symbol/file before deleting it
For each symbol, use an ACTUAL TypeScript LanguageService.findReferences call at its declaration offset. Create the language service with the repo's parsed tsconfig and project files, including relevant project references; preserve the script and output as evidence. Count and list definition references, own-unit-test-only references and live production references separately. Missing/empty results do not prove non-use: verify the symbol resolves and the project loaded correctly. If there is any live reference, exclude it unless it is wholly within the same independently proven unreachable deletion set.
Also search the whole repository, including scripts, Electron entrypoints, Docker files, workflows, .agents/, docs, dynamic imports, string module paths, barrels and package exports. Check public library entrypoints/declarations and external-consumer boundaries. Test-only use is not proof that a public export is safe to remove. When dynamic use or reachability is uncertain, KEEP it and document the uncertainty.
For a file removal, confirm every declared/exported symbol AND non-TypeScript entrypoint/string reference; for parameter plumbing, prove all callers and runtime behavior. Select the smallest cohesive safe set. No proven candidate is a valid NO_CHANGE outcome.

3. Perform a deletion experiment and compare final evidence
Run the following on untouched baseline AND the FINAL candidate tree, retaining command, exit code and output for each. Use repository scripts when available:
- Typecheck, lint, application build AND library build.
- Compare the COMPLETE public declaration tree byte-for-byte: filenames and contents from root, all package exports/subpaths, i18n and lib. Record a manifest/hash comparison from both builds. Run this comparison AFTER all code, plumbing, tests and docs edits. Any missing/added/changed public .d.ts is a failure; do not publish.
- Full test suite, not only selected tests. Do not excuse failures from PR #18417's historical baseline. For each failure, rerun the exact case on this run's untouched SHA in the same environment and compare failure identity and diagnostic. New/different failures block publication. Record baseline failures explicitly; suite counts alone are insufficient.
- Repository map/source-reference consistency checks and applicable pre-commit checks. Review final diff for new lint warnings, accidental format churn, unrelated edits and weakened assertions.
- Smoke affected LIVE user paths with the repo verification skill when applicable. Keep baseline/candidate evidence and disclose the backend: an MSW/mock/no-LLM smoke is only smoke evidence, never a real-backend claim. If a relevant live smoke cannot run, report BLOCKED rather than claim behavior was verified. For genuinely internal types with no UI path, explain why UI smoke is inapplicable.
Keep all checks within the 1800-second automation timeout. Prefer NO_CHANGE/BLOCKED to a partial, unverified deletion PR. Do not replace required checks with inference or CI badges.
