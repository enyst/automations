# Jev English lint experiment

A read-only, stdlib Python script sends public source to Jev 1.13.0. English
policies define corrections; Python extracts AST candidates and supplies exact
locations. Strong signals emit JSON `error` diagnostics with an alternative for
the coding agent. No autonomous agent, builds, GitHub writes, or automatic fixes.

The local automation is **paused**. Dispatch is manual. No recurring run is enabled.

## Run

```sh
# One or more Python files: exit 2 when correction diagnostics are emitted.
JEV_API_KEY=... python3 local-automations/jev-lint/tarball/focused.py path/to/hooks_service.py
# Constant-annotation policy only:
JEV_API_KEY=... python3 local-automations/jev-lint/tarball/focused.py --final-only path/to/constants.py
# No file args: the bounded regression experiment (at most eight calls).
python3 local-automations/jev-lint/tarball/focused.py
# Whole-file comparison and offline request inspection:
python3 local-automations/jev-lint/tarball/main.py --dry-run
```

Read `JEV_API_KEY` or `TYPESAFE_API_KEY` from the environment, or a named automation
secret. This explicitly local macOS experiment can also read the existing
`openhands` / `TYPESAFE_API_KEY` Keychain item into memory. No key is bundled,
printed, or copied to automation settings. Do not send private source without
approval. Syntax errors and API failures are execution failures, not clean checks.

For an agent loop, capture JSON diagnostics and exit code 2, then send each error's
`message`, `location`, and `alternative` back to the coding agent. Recheck after
its edits. This experiment implements that tool-facing interface; it does not
install a hook into an existing agent conversation.

## Questions and gates

`tarball/focused.py` contains three explicit English lint policies:

- `PY_SUPPRESS`: prefer `contextlib.suppress` for ignored exceptions without
  discarding meaningful exception handling; preserve fallback returns.
- `BOOL_SCOPE`: public loading flags must name the resource they load.
- `CONST_FINAL`: module constants must carry `typing.Final[value_type]`.

Each AST candidate gets an independent Noul and a binary Choice question. The
selected gate is Choice `P(correct) >= 0.95`, with Noul `> 0.5` as a contradiction
check. This was selected after the initial experiment. It is an **experimental,
unvalidated threshold**, not a guarantee that a correction is safe. Uncertain
results stay visible in raw answers but emit no error. Alternatives are authored
with the rules, not generated by Jev. Score is inappropriate here: violation is
a classification, not ordered intensity.

Locations are deterministic AST line numbers. A diagnostic also carries a source
snippet hash. API compatibility still requires judgment; renaming a released REST
field needs aliases and deprecation, not a silent breaking change. `Final` is a
static annotation, not runtime immutability. Type aliases and mutable state are
outside that policy. Candidate selection limits coverage (e.g. complex boolean
type annotations and non-Python code are not covered).

## Feature-map current-behavior lint

`tarball/feature_map.py` adds `MAP_CURRENT_BEHAVIOR`: describe current behavior,
not fix history or older checkouts. Once a fix is established, state its behavior
directly. Keep the map clean and concise for the next verification pass. Current
prerequisites, unresolved defects and executable baseline/fix proofs remain valid.
A PR reference alone is not an error.

```sh
python3 local-automations/jev-lint/tarball/feature_map.py \
  --repo /path/to/OpenHands --base <base-sha> --head <head-sha>
# Offline inspection, without credentials or API calls:
python3 local-automations/jev-lint/tarball/feature_map.py \
  --repo /path/to/OpenHands --base <base-sha> --head <head-sha> --dry-run
```

This checks the two-tree diff, not the working tree. It selects added/modified
prose paragraphs in `verify-openhands/references/feature-map/*.md`. It skips
fenced code, deleted text and unchanged paragraphs, and retains new-file line
locations. It sends at most eight batches of twelve paragraphs. Each paragraph
gets the same Noul/Choice pair, with a 0.80 Choice error gate for this rule and
Noul > 0.5 as a contradiction check. Existing Python-rule gates remain 0.95.
Exit 2 means error diagnostics, 1 means execution failure, 0 means no emitted
errors (not proof of a clean map). No automatic edits or agent hook is installed.
The existing paused automation's default Python fixture entrypoint is unchanged;
this diff check is an explicit CLI mode, not a scheduled GitHub integration.

Measured on PR #18437 before and after Engel's two F10 edits: see `RESULTS.md`
and the public-source typed responses in `feature-map-results.json`. At the original 0.95 gate, one of the two old-checkout notes was missed.
Replaying the same responses at 0.80 flags both before correction and neither
afterward. This remains an uncalibrated lint score, not a probability guarantee.

## Cloud deployment (2026-10-15)

Cloud automation `ad72eec2-5dad-44ff-9c23-92a78a9c003a` contains this runtime
bundle; downloaded read-back verified every file. It is inactive for manual use
while the input/notification policy is being decided. The local automation
`fdcbd3c5-a745-4275-b9d2-dd7298d95ef8` is disabled, verified by read-back.
No new runtime source copy was added; this branch remains the source for the
experiment. Cloud Git Sync does not deploy this branch automatically.

Cloud entrypoint is now `python3 pr_lint.py`. It requires an explicit PR target
via arguments or event payload; without one, it skips without classifier calls.
It fetches the PR from GitHub and requires `user.login == "enyst"` before
reading source or classifier credentials. It rechecks author and head before
classification and head/author after it. Other authors, missing identity, drafts
and closed PRs do not run. Event author claims are never trusted.

`pr_lint.py --repository OpenHands/OpenHands --pr 18437` checks added/modified
Python candidates and feature-map prose, reading public source at the exact head.
Incomplete relevant patches/source fail rather than claiming a clean check.
Output includes JSON in run logs. The deployed publisher posts findings as
SmolPaws using the existing Cloud `SMOLPAWS_TOKEN`, after checking `/user`
returns exactly `smolpaws`. `--no-publish` keeps a run read-only. The feature-map CLI
is included, but needs an explicit repository, base and head; no target is selected
automatically. It has not been dispatched in Cloud yet. Findings on changed RIGHT-side diff lines become inline review comments at the
checked commit. Lines outside the diff become normal comments with a pinned
file/line link. Every comment starts exactly with `Jev-lint warning 🐾` and a
newline, followed by the rule, suggested correction and uncalibrated score.
Only public repositories and open, non-draft PRs authored by `enyst` qualify.
The author/head/state are rechecked before each write. GitHub cannot make that
check and write atomic; inline comments are pinned to the checked commit.

A marker based on rule, file path and source-snippet hash suppresses repeated
warnings across runs, even when a line moves. Only markers on SmolPaws comments
count. An ambiguous failed POST is not retried within a run; the next run reads
comments before posting. Simultaneous runs are not serialized yet, so concurrent
runs could still race and duplicate a warning. No approval/request-changes review
is submitted, and no automatic target discovery or PR-event subscription is
installed. The Cloud definition remains inactive. No live posting trial has run. `cloud-deployment.json` records the bundle identity, not a successful
Cloud execution. The existing Cloud TYPESAFE_API_KEY is reused; no secret copied.
